# Claude Code + GTDに切り替えたら、タスク管理が育ち始めた

**この記事について**: Claude Code や ChatGPT 等の AI ツールで日常業務をこなしながら、タスク管理だけ Things 3 や Todoist 等の専用アプリを使っている人に向けて書いた。「AIでGTDを回すとどう変わるか」を体験の時系列で報告する。

---

## 「AIで仕事してるのに、タスクだけ別のアプリに書いてる」

Claude Code で作業していると、こういう瞬間がある。

コードレビューの途中で「あ、この設計がそもそも問題かも」と気づく。手を止めて Things 3 を開いて、タイトルを考えて、打ち込む。「設計を見直す」。

画面を閉じて作業に戻る。

3日後にそのタスクを見る。「設計を見直す」——何の設計を、なぜ見直すのか、何も書いてない。

あのとき Claude Code のチャット上で何かを見ていた、という記憶はある。でも Things 3 にはその文脈が一切ない。「まあいいか」でスキップする。

これを何度繰り返しても、外部のタスク管理ツールとAIツールの間にある断絶は埋まらない。なぜなら、これは運用の問題ではなく、構造の問題だからだ。

---

## 問題の本質は「文脈の分断」にある

タスクが機能するかどうかは、後から見たときに「なぜこれをやるのか」が追えるかどうかにかかっている。

GTD でいう「次のアクション」の定義がここにある。私の運用では、タスクには背景・目的・次の具体的な1アクションが必要だと考えている。タイトルだけのタスクは、後から動けない。

問題は、AIツールと外部タスク管理ツールの間でコンテキストを橋渡しする仕組みがないことだ。

- 作業文脈（チャット履歴・コード・気づき）は AI ツール側にある
- タスクは Things 3 や Todoist 側にある
- 橋渡しするのは、手動でのコピペだ

コピペが面倒だから省略する。省略すると文脈のないタスクだけが残る。文脈のないタスクは後から動けないので、スキップする。スキップが増えると GTD が回らなくなる。

これは努力や習慣で乗り越えられる問題ではない。AIツールの外にタスク管理ツールがある以上、原理的に文脈の自動伝達はできない。

---

## 発想の転換：Things 3 は「買う」、Claude Code + GTD は「育てる」

Things 3 や Todoist は完成されたツールを「買う」体験だ。

機能は豊富で、UIは洗練されている。しかし、ツールのルールが自分の仕事のやり方と合わなかったとき、選択肢は2つしかない。自分がツールに合わせるか、使うのをやめるか。

GTDは「ルール」であってツールではない。収集・処理・整理・レビュー・実行の流れが本質で、ツールはそのルールを実装する「器」にすぎない。完成品を買うと、「ツールのルール」でGTDを実装することになる。

Claude Code + GTD の組み合わせは、自分の仕事のルールをそのまま実装できる。

- CLAUDE.md に自分の収集ルール・分類ルール・レビューのタイミングを書く
- memory に過去の判断パターンや好みが蓄積されていく
- 蓄積するほど、道具が自分の仕事の形を知っていく

Things 3 を10年使っても、Things 3 は同じ Things 3 のままだ。Claude Code + GTD は使い続けるほど自分の仕事の形に近づいていく。これが「育てる」の正体だ。

---

## Claude Code + GTDに切り替えると何が変わるか：3段階の変化

この組み合わせを使い始めて、何が変わったかを時系列で報告する。

### 使い始め直後：収集の摩擦がゼロになった

最初に変わったのは、タスクを記録するコストだ。

以前は Things 3 を開いて、タイトルを考えて、必要なら説明を書いて……という手順が必要だった。面倒だから、後でまとめてやろうと思って、結局やらない。これが Inbox に入れない理由だった。

Claude Code に「これ、タスクにしといて」と話しかけるだけになってから、それがなくなった。

正直に言うと、最初はサボりたかっただけだ。アプリを切り替えるのが面倒だから、隣にいる AI に話しかけた。それが習慣化につながった。

もう一つ大きかったのは、「完璧に書かなくていい」という解放感だ。雑に投げても、AI が直前の会話の文脈から背景を補完してくれる。「あの設計が問題かも」と言うだけで、「どのファイルで話していたか」「なぜ問題だと思ったか」を含めてタスクを作ってくれる。後から見ても、なぜこのタスクを作ったかが追える。

GTD の Inbox が機能し始めたのは、このタイミングだった。

### 1週間後：AIが先に提案してくるようになった

使い続けると、方向が逆転し始める。

作業しているとAIの方から「これ、Issueにしますか？」と提案してくるようになった。会話の文脈から「これはタスク化したほうがいい」を検知して、自分から言ってくる。これはAIが自律的に学習しているのではなく、CLAUDE.md に書いたルール（「タスク化すべき兆候があれば提案する」等）に基づいて動作している。

CLAUDE.md に自分のルールが蓄積されているほど、提案の精度が上がる。「次のアクションを必ず1つ定義する」というルールを入れておくと、タスク作成時に次のアクションを一緒に考えてくれるようになる。

### 成熟期：タスクが蓄積するほど関連を把握する

タスクが蓄積してくると、処理・整理フェーズでの提案が増える。

「このタスク終わったら関連の「設計書レビュー」もdoneにしますか？」「同じプロジェクトのタスクが止まっています」という気づきを先に言ってくれる。

道具が「自分の仕事の形」を知っている状態になる、という感覚がある。

---

## 育てる仕組み：CLAUDE.md と memory が自分専用化の核

技術的な仕組みをシンプルに説明する。

「自分のことを知っている AI 」の実体は3層だ。

| 層 | 実体 | 範囲 |
|---|---|---|
| 今この瞬間の文脈 | 会話履歴 | セッション内のみ |
| プロジェクトのルール | CLAUDE.md | 常時・永続 |
| 過去のやり取りを記録したメモ | memory | 常時・育つ |

CLAUDE.md は自分の仕事のルールブックだ。「このプロジェクトのタスクはこのラベルを使う」「週次レビューはこのタイミングで実施する」——自分の GTD 実装をそのまま書ける。

memory はセッションをまたいで AI が参照するメモだ。過去の判断・好みをファイルに書き込んでおくことで、「この人はこういうタスクの切り方をする」を AI がセッションをまたいで把握し続けられる。

重要なのは、**自分専用になるのは /todo スキルをコピーした時点ではない**という点だ。CLAUDE.md と memory を自分の仕事のルールで育てた時点から、ようやく自分専用の道具になる。

たとえば私が実際に書いているルールはこういったものだ。「Inbox に未処理タスクがある場合は、次のアクション提案より先に仕分けを促す」「next タスクには必ず次の具体的な1アクションを定義する」。こうした記述が CLAUDE.md に積み重なるほど、AI の提案が自分の GTD 運用と噛み合っていく。

---

## 「でも専用ツールのほうが使いやすい」への回答

これが最大の反論だと思うので、正面から答える。

Things 3 や Todoist が使いやすい人は、そのまま使えばいい。これはその否定ではない。「ツールに自分を合わせるのが苦痛」「なぜか続かない」という人への提案だ。

使いやすさの定義が、そもそも違う。

- 専用ツール: UIが整っている / 表示がきれい / 操作が決まっている
- AIタスク管理: 話しかけるだけ / 文脈が残る / 提案が返ってくる

「整ったUIで記録したいか」vs「文脈込みで記録されたいか」——後から追いやすいのはどちらか、という問いに変わる。

もう一つ。「AI付きの Todoist でいいんじゃないか」という反論もある。

違いは場所だ。

- AI付き Todoist = 「タスク管理する場所」に AI が付く
- 作業環境 AI + タスク管理 = 「作業している場所（会話）」に AI がいる

後者は前者では原理的に真似できない。作業している場所と文脈が同じだから、橋渡しのコストがゼロになる。

---

## 文脈が残り、育てるほど合ってくる——AIタスク管理の本質

外部のタスク管理ツールが続かなかった理由は、サボっていたわけでも、GTD の理解が足りなかったわけでもなかった。作業環境とタスク管理の間に文脈が伝わらない、構造的な断絶があった。

AIツールで仕事をしているなら、タスク管理を同じ環境に置くと、その断絶がなくなる。

最初の変化は「めんどくさいから話しかけた」という、サボりたい気持ちから来た。それが定着につながった。使い続けるうちに CLAUDE.md と memory に自分の仕事のルールと判断パターンが蓄積され、道具が自分の形に近づいていき、提案が返ってくるようになった。

GTDツールは買うものではなく、育てるものだ——そう実感するようになったのは、この体験を経てからだ。

明日から始めるなら、まず1つだけ試してほしい。今日の作業中に「あ、これ後でやらないと」と気づいた瞬間、専用アプリを開くのをやめて、そのまま AI に「これタスクにしといて」と打つだけでいい。それだけだ。タスクのタイトルを考える必要も、アプリを切り替える必要もない。どんな文脈でそのタスクが生まれたかが自動的に残り、3日後に「なんのタスクだっけ」と首をかしげる回数が確実に減る。まず今日1回、話しかけてみることから始まる。

この記事で書いた「育てる」の中身、つまり CLAUDE.md と memory をどう設計するか・GTD のサイクルをどう AI と回すかは、Vol.5「任せるまで」で詳しく扱う予定だ。
