## ☀️ 「おはよう」から始まる GTD

朝、PCを開いてコーヒーを淹れて、Claude Code に「おはよう、今日のタスク見せて」と打つ。

返ってきたのはダッシュボード。今日やること、Inbox に溜まった未処理タスク、期限が迫っているもの。一覧で見ると頭の中のモヤモヤが一瞬で可視化されます。

ここから10分後、バラバラだったタスクがプロジェクトとして構造化され、今日の最初の一歩まで決まっていました。

やったことは**チャットで会話しただけ**です。

この記事は `/todo` シリーズの第4弾。今回は「朝の10分ルーティン」に焦点を当てて、対話で GTD が回る体験を書きます。

## 📋 ダッシュボードで「今日」を把握する

`/todo dashboard` と打つだけで、こんな画面が出てきます。

```
📊 Dashboard — 2026-04-07 (Mon)

── Today ──────────────────────
  🎯 #314  体重を測って記録する  📅 today
  🎯 #313  朝の散歩  📅 today
  🎯 #279  最小アクションを1つ選ぶ  📅 today
  🎯 #278  メール確認  📅 today

── Inbox (4) ──────────────────
  📥 #309  同僚のPC発送手配
  📥 #310  デバイス返却申請
  📥 #311  集荷用に梱包を実施
  📥 #312  集荷日にPCを受け渡す
```

今日やること4件、Inbox に未処理が4件。ポイントは **Inbox がゼロじゃないこと**。GTD の大原則として、Inbox に未処理タスクが残っている状態は「頭の中に荷物が残っている状態」と同じ。まずこいつらを片付けます。

## 🔀 Inbox 仕分け — 対話で1件ずつ判断していく

Claude が1件ずつ聞いてくるので、カテゴリを答えるだけ。2分で4件が片付きました。

| # | タスク | 判断 | 理由 |
|---|--------|------|------|
| #309 | 同僚のPC発送手配 | 📁 project | 複数ステップある親タスク |
| #310 | デバイス返却申請 | 🎯 next | すぐやれる |
| #311 | 集荷用に梱包を実施 | 🎯 next | すぐやれる |
| #312 | 集荷日にPCを受け渡す | ⏳ waiting | 集荷日待ち |

実は #309 は最初「next」と答えました。でも残り3件を仕分けているうちに「これ、全部 PC 発送に関連してるな」と気づいた。

```
自分: 「あ、#309 は next じゃなくて project にして。
       他のタスクをぶら下げる親にしたい」
Claude: → project に変更しました ✅
```

**ここが対話の強み**。一度決めたことをその場で修正できる。タスクアプリだと画面を行き来する手間があるけど、チャットなら「やっぱりこっち」の一言で終わり。会話に答えるだけで Inbox がゼロになるのは、思った以上に気持ちいい体験です。

## 🎯 最小アクション提案 — AI が「今日の一歩」を選んでくれる

Inbox がゼロになったら、次は「今日、何から手を付けるか」。Claude に「今日の最小アクションを提案して」と聞くと、Next Actions を分析して候補を出してくれます。

```
🎯 最小アクション候補:
  #187 返却方法の確認
  ├── 所要時間: 5〜10分
  ├── 理由: 後続タスク (#311→#312) の起点
  └── 効果: PC発送プロジェクト全体が動き出す
```

ここで面白いことが起きました。Claude が「#187 → #311 → #312 の流れがある」と指摘したことで、バラバラだったタスクが1本の線で繋がったのです。

```
自分: 「じゃあ #187, #310, #311, #312 を全部 #309 のプロジェクトに紐付けて」
Claude: → 4件すべてを project:#309 にリンクしました ✅
```

```
📁 #309 同僚のPC発送手配
├── 🎯 #187 返却方法の確認       ← 今日これから着手
├── 🎯 #310 デバイス返却申請
├── 🎯 #311 集荷用に梱包を実施
└── ⏳ #312 集荷日にPCを受け渡す  ← 集荷日まで待ち
```

自分では「バラバラのタスク」としか認識していなかったものが、Claude の提案をきっかけに **1つのプロジェクトとして構造化された**。最小アクション提案が単なる「今日やること選び」ではなく、タスク全体の構造を浮かび上がらせる装置になっていました。

## 🧠 使いながらルールを育てる — メモリとの共進化

朝のセッション、もう1つの収穫は **運用ルールの発見と保存**。

```
自分: 「最小アクション候補に、waiting の進捗確認も入れてほしい。
       集荷日がいつか確認するのは小さなアクションでしょ？」
Claude: 「確かに。waiting タスクの『進捗確認』も候補に含めるルールを
        保存します」→ メモリに保存 ✅

自分: 「あと、Inbox にタスクが残ってる状態で最小アクション提案しないで。
       まず仕分けが先」
Claude: 「GTD の原則通りですね。前提条件として保存します」
        → メモリに保存 ✅
```

Claude Code のメモリ機能は、こうした運用ルールを会話の中で拾い上げて永続化します。次回の朝セッションでは、**最初から**このルールが適用された状態で始まる。

使えば使うほどシステムが自分の好みに最適化されていく。GTD のツール自体が「育つ」という感覚。これは静的なタスクアプリでは得られない体験です。

## 💡 なぜ「Claude × /todo」なのか

朝の10分を振り返ると、普通のタスクアプリとは質的に違うことが起きていました。

**「気づき」をくれる。** タスクアプリは入力したものを表示するだけ。Claude は「#187→#311→#312の流れがありますね」とタスク間の関係性を指摘してくれた。人間が見落としていた構造を、AI が浮かび上がらせる。

**自然言語で雑に指示できる。** 「やっぱり project へ」「対象アクションをプロジェクトに紐付けて」。こんな曖昧な指示でも意図を汲んで実行してくれる。コマンドの構文を覚える必要がない。

**ルールが会話から生まれる。** 「waiting も候補に入れて」という何気ない一言がルールになり、次回から自動適用される。静的なアプリなら設定画面を開いてチェックボックスを探す作業が、チャットの一言で終わる。

**判断の壁打ち相手になる。** 「これは next？ waiting？」と迷ったとき、タスクの性質を踏まえた助言がもらえる。一人で悩まずに済む。

## ✨ まとめ: 朝10分で手に入るもの

今朝の10分で得られたのは、4つの成果でした。

| 成果 | 何が起きたか |
|------|-------------|
| **Inbox ゼロ** | 未処理タスク4件を仕分け → 頭スッキリ |
| **最小アクション決定** | 「返却方法の確認」から着手 → 迷いゼロ |
| **プロジェクト構造化** | バラバラのタスクが1プロジェクトに集約 |
| **運用ルール蓄積** | 2つのルールをメモリに保存 → 次回から自動適用 |

GTD の理想は「頭を空にして、信頼できるシステムに全部預ける」こと。でもその運用自体が面倒で挫折する人が多い（自分もそうでした）。

Claude Code との対話で GTD を回すと、**仕分けが会話になり、構造化が提案になり、ルール策定がチャットになる**。面倒な「管理作業」が、朝のコーヒーを飲みながらの雑談に変わります。
