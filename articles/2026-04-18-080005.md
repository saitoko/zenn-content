## リモートで実行中のエージェントを止めるのって難しくないですか

Claude CodeのRoutinesでエージェントをリモート自動実行していると、「あ、これはまずい」と気づいたときに止める手段がなくて困った経験はないでしょうか。

ローカルで実行しているセッションなら `Escape` を押せばいい。でも Routines（スケジュール実行）でリモートが動いているとき、その手が使えない。「監視はできるけど介入できない」という状態が続いていました。

2026-04-17、その状況が変わりました。

---

## Desktop新UIでリモートCEOセッションに直接メッセージを送れた

secretaryエージェントがZennのgit pushを実行しようとしていました。そのとき `index.lock` ファイルの編集許可を求めるプロンプトが上がってきた。**権限不足でsecretaryはすでに止まっていた状態**です。

問題は、**ローカルのCode環境でそのpushをすでに済ませていた**ことです。secretaryが権限を得てそのまま実行すると二重pushになる。

そこでDesktopアプリからリモートCEOセッションへメッセージを送りました。

> 「Zenn pushしないで」

「止めた」というより「すでに止まっていた状態のCEOに、コンテキスト（理由）を伝えた」が正確です。セッションはそのまま終了し、二重pushを回避できました。

もう一つの使い方として、**失敗したRoutinesセッションの原因究明**があります。失敗したリモートセッションをDesktopで開いて「なぜ失敗した？」と聞けますし、`--teleport` でローカルに引き取って深掘り調査することも可能です。エラーログを別途探し回る必要がなく、デバッグが格段に楽になりました。

### Routinesセッションへのメッセージ送信

Desktopのサイドバーにはセッション一覧が表示され、Routinesの各実行も通常のセッションとして並びます。公式ドキュメント（https://code.claude.com/docs/en/routines）の表現では「continue the conversation」——要するに、実行中・実行済みを問わず会話を継続できる機能です。Routines専用の特別な仕組みがあるわけではなく、セッションを開いてメッセージを送るだけです。

介入の経路は「Desktop → リモートCEO → secretary」です。secretaryはCEOセッションのバックグラウンドで動くサブエージェントであり、メッセージはCEOに届いてCEOがsecretaryを制御した。「エージェントへの直接割り込み」ではなく「CEOへの割り込み→CEOがサブエージェントを制御」という構造が核心です。

## さらに強力な方法——`--teleport` でローカルに引き継ぐ

「リモートセッションをそのままローカルCLIに持ってくる」方法が `--teleport` です。

公式ドキュメントによれば、用途は「クラウドセッションをローカルCLIに引き継ぐ」こと。起動方法は2通りあります。

```bash
# 一覧ピッカーから選ぶ
claude --teleport

# セッションIDを直接指定する
claude --teleport session_013xbNiQ15GBryqoEvKSDr1T
```

最初の試行では以下のエラーが出ました。

```
Git working directory is not clean. Please commit or stash your changes before using --teleport.
```

未コミットの変更を `git stash` してから再実行したところ、正常にローカルへ引き継げました。

CLIセッション内からは `/teleport`（短縮形: `/tp`）でも同じ操作が可能です。

実際に実行したところ、リモートで走っていたセッションをローカルのCLIに引き継げました。

## できないこと・注意点

### `--teleport` の使用条件

以下がそろっていないと使えません（公式ドキュメント確認済み）。

- **Gitの作業ディレクトリがクリーンであること**。未コミットの変更が残っていると `Git working directory is not clean` エラーが出て失敗します。実際に最初の試行でこのエラーを踏みました
- **claude.aiアカウントで認証済みであること**。APIキー認証・Amazon Bedrock・Google Vertex AI経由では使用不可
- **ブランチがリモートにプッシュ済みであること**

どのバージョンで追加されたかは未確認。ただしv2.1.108の公式CHANGELOG（[github.com/anthropics/claude-code](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)）に`--teleport`関連のバグ修正が2件記録されており、この時点で存在していたことは確認できる。

### Desktop経由のメッセージ送信

常時使えるかは未確認です。「セッションが生きている間だけ」なのか「完了済みセッションにも送れる」のか、追加検証が必要です。

## まとめ

- DesktopのサイドバーからRoutinesのリモートCEOセッションを開き、「continue the conversation」としてメッセージを送れた（2026-04-17実測）
- 二重pushを防ぐインシデント回避に実際に使った
- 今回の例はCEOセッション構成だが、親エージェントが存在する構成なら同様に応用できる
- `--teleport`（または `/teleport` / `/tp`）でリモートをローカルCLIに引き継ぐことも可能（Gitクリーン・アカウント認証・ブランチpush済みが条件）
- どのバージョンから使えるかは未確認

「監視」「横から介入」「手元に引き戻す」という手段が揃ってきた話でした。
