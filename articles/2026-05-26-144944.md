**この記事の要点（2026-05-18 執筆時点）**: Claude Code v2.1.139（2026-05-11 リリース）で `/goal` コマンドが研究プレビューとして公開された。完了条件を自然言語で書くだけで、Claude が「まだ達成していない」と自己判断して次のターンへ進む自律ループが実現する。本記事ではコマンドの仕組み・実際の使用例・Routines との組み合わせ・現時点の限界を整理する。

---

ゴールを書いたら、あとは Claude が勝手にやってくれる時代が来た——少し大げさに聞こえるかもしれないが、2026-05-11 にリリースされた `/goal` コマンドは、それに近い体験を提供し始めている。

この記事自体がその実例だ。筆者はこのセッションの冒頭で次のようなゴールを設定した。

```
今作成したネタ帳とこのセッションの対話を元に、"/goal"利用例の記事を作成し、
３軸品質ゲート90点以上となること。
```

その後 Claude は、ユーザーに都度プロンプトを求めることなく、Playbook 確認 → writer 委任 → 品質ゲートへ向けた執筆という複数ステップを自律実行している。読んでいるこの記事が、`/goal` の典型的な用途そのものだ。

---

## /goal とは何か——従来のプロンプトとの違い

### 1回聞いたら終わり、が変わる

Claude Code のこれまでの動作は「1ターン入力→1ターン応答→停止」が基本だった。「テストが全部グリーンになるまでデバッグして」と指示しても、Claude は1ターン分だけ作業して止まる。残りのデバッグを続けるには、ユーザーが再度「続けて」と入力しなければならない。

`/goal` はこのループを Claude 自身が回すようにする仕組みだ。公式 changelog（v2.1.139、出典: [docs.anthropic.com/en/release-notes/claude-code](https://docs.anthropic.com/en/release-notes/claude-code)）によれば、「完了条件を設定すると Claude がその条件が満たされるまでターンをまたいで作業を継続する」と記載されている。

### 研究プレビューという前提

ただし、現時点（2026-05-18）の `/goal` は **研究プレビュー（Research Preview）** だ。機能は動いているが、仕様変更・不安定な挙動・予期せぬ停止が起きる可能性がある。本記事で紹介する使い方もすべて「現時点のスナップショット」として読んでほしい。

> 研究プレビューの機能は、将来的に仕様が変わる・廃止になる・名称が変わる可能性がある。安定運用の前に公式ドキュメントで最新の扱いを確認すること。

### インタラクティブ・-p・Remote Control に対応

公式 changelog によれば、`/goal` はインタラクティブモード（通常の対話セッション）・`-p`（非インタラクティブ/パイプ入力）・Remote Control（外部からの制御）の3つの実行形態に対応している（出典: docs.anthropic.com/en/release-notes/claude-code）。用途に応じて使い分けられる設計になっている。

## 実際の使い方

### 基本的な使い方

`/goal` の使い方はシンプルだ。Claude Code のプロンプトで `/goal` と入力し、続けて完了条件を自然言語で書く。

```
/goal テストが全件グリーンになること
```

```
/goal READMEにインストール手順が追記され、動作確認済みであること
```

Claude はこのゴールを「評価軸」として持ち、各ターンの作業後に「条件を満たしたか」を自己確認する。満たしていなければ次のアクションを自律的に続ける。経過時間・ターン数・消費トークン数はリアルタイムで表示される（出典: docs.anthropic.com/en/release-notes/claude-code）。

### このセッションでの実例

筆者は今回のセッションで以下のゴールを設定した。

```
今作成したネタ帳とこのセッションの対話を元に、"/goal"利用例の記事を作成し、
３軸品質ゲート90点以上となること。
```

Claude はその後、次の手順を自律実行した。

1. Playbook（`ops/playbooks/article/writing.md`）を確認
2. ネタ帳・changelog レポート・対話アーカイブを参照
3. 記事の frontmatter・構成を設計
4. 本文執筆（今読んでいるこのファイル）

ユーザーの追加入力なしに、複数のファイル参照と執筆作業が連続して進んでいる。これが `/goal` の典型的な動作だ。

なお、正直に書いておくと、すべてがスムーズだったわけではない。各ステップで Claude が Playbook の内容を確認し、手順に漏れがないかチェックする工程が入るため、シンプルなプロンプトよりも実行時間は長くなった。「自律」とはいえ、内部では慎重なステップ確認が動いている。

## Routines × /goal で「夜間自動実行」を試す

### 三位一体のフロー

Agent View（`claude agents` コマンドで起動、全セッション一覧監視）・Routines（スケジュール実行）・`/goal`（自律継続）の3つが組み合わさると、「スケジュール起動 → ゴール到達まで自律継続」フローが実現できる（出典: [claude-world.com](https://claude-world.com/articles/claude-code-21139-release/)）。

実際の手順イメージ（参考として）:

1. Routines で「毎朝6時にレポート生成タスクを起動」と登録する
2. 起動時のコマンドに `/goal 全データソースからレポートを生成し、`output/report.md` に保存されていること` を含める
3. Agent View で起動したセッションの進捗を確認できる

これは「定期レポート生成」「毎朝のログ集計」「週次まとめ記事の下書き」といった繰り返し作業に応用できると考えられる（意見）。Routines の設定方法については [Claude Code 公式ドキュメント](https://docs.anthropic.com/en/docs/claude-code/settings) を参照してほしい。

### 「完全放置」には注意が必要

「夜間に完全放置でいい？」という疑問は正直なところで、現時点では **注意が必要** だ。

研究プレビューの `/goal` は、予期せず停止することがある。エラー状態でスタックしたまま進まないケースも初期採用者から報告されている（出典: [explainx.ai](https://explainx.ai/blog/claude-code-goal-command-long-running-agents-2026)、初期ユーザー報告）。長時間動き続けた実例がある一方で、同じ状況で途中停止した報告もある。

現実的な運用としては、「Agent View で朝チェックして、止まっていたら手動で再開する」というハーフオート運用が安全だと考えられる（意見）。完全放置で確実に完走するレベルには、もう少し安定化が必要な印象だ。

## 注意点・現時点の限界

### コスト：長時間動かすほど増える

`/goal` はターンをまたぐほどトークンを消費する。1ゴールあたりのターン数が増えれば増えるほどコストも積み上がる。

Claude Code は複数プランで利用可能だが（Pro/Max/Team/Enterprise/API 全対応、出典: 公式情報）、`/goal` で複数ターンを自律実行する場合、**Pro プランの月額制限に注意が必要**だ。筆者の使用感では、ファイル操作を伴う中規模タスク（記事1本の執筆）で数十ターン動くこともある。本記事のような制作規模では Max プランが現実的だと考えられる（意見。正確な消費量はタスク内容・バージョンによって変わるため、公式の料金確認を推奨する）。プランごとの料金は[公式料金ページ](https://www.anthropic.com/pricing)で確認できる。

### ハング問題：v2.1.140 でひとつ修正済み

v2.1.139 で `/goal` が導入された直後、`disableAllHooks` または `allowManagedHooksOnly` 設定時にハングする問題が確認され、v2.1.140 で修正された（出典: docs.anthropic.com/en/release-notes/claude-code）。研究プレビューらしくリリースと修正が素早く回っている状態だ。

### コンテキスト管理：System Prompt Compaction が補助

長時間セッションで `/goal` を使うと、コンテキストウィンドウが膨らむ問題がある。v2.1.139 と同タイミングで導入された System Prompt Compaction が自動的にコンテキストをトリミングする仕組みを提供している（出典: [Geeky Gadgets](https://www.geeky-gadgets.com/claude-code-agent-view-update/)）。とはいえ、超長時間のゴール（「数日かけて動き続けた」という初期採用者報告もある、出典: explainx.ai）では、コンテキスト管理の設計が重要になる。

### エラー時は人間が手動介入

現状の `/goal` には、エラー発生時の自動リカバリ機能は備わっていない（公式情報での言及なし）。ツール呼び出しが失敗したり予期せぬ状態に陥ったりした場合、Claude が止まる・ループするといった事態になりうる。重要なタスクに使うときはエラー時の手動補完フローを準備しておくことを推奨する。

## /goalコマンドの現状評価と今後の展望——自律エージェントを試すなら今

`/goal` コマンドは、Claude Code の「1ターン1応答」という制約を一歩踏み越えるものだ。完了条件を自然言語で書くだけで、複数ステップの自律実行が始まる体験は、AIエージェントとの協働の新しい形を示している。

現時点での評価をまとめると:

- **良い点**: 設定が簡単（1行の自然言語）、ターン数・時間・トークンがリアルタイム表示、Routines との組み合わせで定期自動化の基盤になりうる
- **注意点**: 研究プレビューゆえの不安定さ、コスト増加リスク、エラー時は手動介入が必要

Anthropic が `/goal` を研究プレビューとして公開したのは、実際のユーザーフィードバックを集めながら安定化させる意図があると考えられる（意見）。次のバージョンアップでエラー回復・再開機能が追加されれば、完全放置型の自動化が現実的になってくるだろう。今がちょうど「使いながら学ぶ」タイミングだ。
