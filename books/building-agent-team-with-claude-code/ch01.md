# 第1章 Claude Code とは何か（CLI・Pro/Max・他ツールとの違い）

Claude Code は、Claude の Web チャット画面で使う Claude とどう違うのか。Cursor や GitHub Copilot とはどう使い分けるのか。Pro プランで始めていいのか、Max が必要なのか。

この章では、これらの問いに「1人で開発しているエンジニア」の視点で答えます。読み終えたとき、Claude Code を選ぶ理由・始め方・自分のプラン選択の基準が手に入っています。

---

## Claude Code は「チャット画面の Claude」ではない

Anthropic は複数の Claude 製品を提供しています。最もよく知られているのは Web ブラウザやスマートフォンから使える Claude（claude.ai）ですが、Claude Code はその兄弟ではありません。

Claude Code は **CLI（コマンドラインインタフェース）ツール**です。ターミナルで起動し、プロジェクトのディレクトリで実行します。起動すると Claude Code はカレントディレクトリのファイル構造を読み込み、ファイルを読み書きし、コマンドを実行します。

「チャット画面でコード生成の質問をして、回答をエディタにペーストする」作業との最大の違いは、**Claude Code がファイルシステムと直接やり取りする**点です。「src/utils/date-format.ts に関数を追加して」と伝えれば、Claude Code は実際にそのファイルを開いて書き換えます。コピペする必要がありません。

---

## Claude Code の4つの特徴

### 1. コードベースを文脈として読み込む

Claude Code は起動したディレクトリのファイル構造を探索します。どのファイルがどこにあるか、どんなライブラリを使っているか、テストはどのディレクトリに置いているか——こうした文脈を持った状態で作業を引き受けます。

「既存コードに合わせたスタイルで関数を追加して」と頼んだとき、既存ファイルを読まずに生成するのではなく、実際に周辺ファイルを Read して命名規則・型定義・エラーハンドリングのパターンを確認した上で実装します。

### 2. `CLAUDE.md` でプロジェクト固有のルールを持続させる

プロジェクトルートに `CLAUDE.md` を置くと、Claude Code はセッションのたびにそのファイルを読み込みます。「このプロジェクトでは TypeScript strict モードを使っている」「テストは Vitest で書く」「コミットメッセージは英語で」——こうしたルールを毎回プロンプトに書かなくて済みます。

`CLAUDE.md` の書き方は第2章で詳しく扱います。

### 3. ファイルを読み書きし、コマンドを実行する権限を持つ

Claude Code は Read・Write・Edit・Bash・Grep・Glob といったツールを持っています。ファイルを読み、書き換え、シェルコマンドを実行できます。これは Web のチャット画面では持てない権限です。

権限を持つということは、間違った操作をしたときの影響も大きくなります。第7章で「サブエージェントに何の権限を渡すか」を細かく設計する理由はここにあります。

### 4. サブエージェントを起動して並列で動かせる

Claude Code は自分とは別のサブエージェントを呼び出す仕組みを持っています。`.claude/agents/` に定義ファイルを置けば、メインセッションから「reviewer を呼んでこのコードを見てもらって」と指示できます。reviewer は独立したプロセスで、独自のシステムプロンプト・独自のツール権限を持って動きます。

この仕組みが、本書の中心テーマです。

## Cursor・GitHub Copilot との使い分け

Claude Code、Cursor、GitHub Copilot は、それぞれ違うレイヤーで機能します。使い分けを整理します。

| ツール | 主な動作環境 | 得意な場面 |
|--------|------------|----------|
| GitHub Copilot | エディタ内（VS Code 等）の補完 | 行・関数レベルのリアルタイム補完。キーを打ちながら候補が出る |
| Cursor | Cursor エディタ内のチャット・エディット | ファイル単位の変更・リファクタリング。エディタ一体型で操作が速い |
| Claude Code | ターミナル（CLI）から実行 | プロジェクト横断の作業・複数ファイルの連携変更・サブエージェントとの協調 |

これらは競合よりも補完の関係です。

> **著者の使い分け一例**
>
> コードを打つときは Copilot の補完を使い、ある程度まとまった機能追加・リファクタリングは Claude Code、その Claude Code の作業結果を Cursor のエディタで確認・微調整する、という流れになることがあります。

**Claude Code が特に力を発揮する場面:**

- 複数ファイルにまたがる変更（インタフェース追加→各実装クラスへの反映→テスト更新）
- プロジェクトの構成・依存関係を理解した上での設計相談
- 繰り返し発生する作業（コミット前レビュー・API定義からの型生成）を自動化したいとき
- 1人では観点が不足する場面でサブエージェントを役割として置いたいとき

**Cursor が向いている場面:**

- エディタ内でその場でコードを修正・リファクタリングしたい
- UI を見ながら細かい編集を繰り返したい

**GitHub Copilot が向いている場面:**

- 関数・変数の補完を打鍵しながらリアルタイムで受け取りたい
- コーディング中の「次の一手」を候補として見ながら選びたい

## CLI のセットアップ

セットアップは3ステップです。

**前提条件:**

- Anthropic の Claude Pro または Max プランを契約済みであること（または API キーを持っていること）

**ステップ1: インストールする**

macOS・Linux・WSL の場合:

```
curl -fsSL https://claude.ai/install.sh | bash
```

Windows（PowerShell）の場合:

```
irm https://claude.ai/install.ps1 | iex
```

インストールが完了すると、`claude` コマンドがどのディレクトリからでも使えます。Node.js は不要です。

**ステップ2: プロジェクトディレクトリで起動する**

```
cd your-project
claude
```

初回起動時に認証フローが走ります。Claude のアカウントでログインすると、Pro/Max プランの利用枠が使える状態になります。API キーで接続することもできます（詳細は公式ドキュメントを参照してください）。

**ステップ3: 動作確認**

起動すると対話モードになります。「このプロジェクトの構成を説明して」と入力すると、ディレクトリ構造を探索した上で応答が返ります。ここで「プロジェクトの構成を理解している応答」が返れば、セットアップ完了です。

終了するには `exit` と入力するか、`Ctrl + C` を2回押してください。セッションを終了すると、その中でやり取りした内容は次回のセッションに自動では引き継がれません（`claude --continue` のように前回セッションを再開するコマンドもありますが、原則は使い切りと考えてください。プロジェクトのルール・文脈を持続させる仕組みは第2章の `CLAUDE.md` で扱います）。

> **注記: バージョンは常に変化します**
>
> Claude Code は頻繁に更新されています（2026年6月時点でバージョン 2.1.x）。本書が参照している挙動と実機が異なる場合は、公式ドキュメント（https://code.claude.com/docs）が最新情報の正典です。Native インストール版はバックグラウンドで自動更新されます。手動で更新する場合は `claude update` を実行してください。

## プラン選択の考え方（概要）

Claude Code の利用は、Anthropic の Claude サブスクリプション（Pro または Max）と連携します。

試し始める段階なら **Pro から始める**のが現実的です。Pro の利用枠に毎日当たるようになってきたら、Max への移行を検討します。

プラン別の価格と詳細な判断基準（週あたりの利用時間・ROI の考え方）は第14章で扱います。ここではまず「Pro から始めて、当たったら上げる」という方針だけ持っておけば十分です。

> **補足: 対話型とAgent SDK利用で枠が分かれている**
>
> 2026年6月以降、`claude -p`（非対話実行）やエージェントSDK経由の利用は、対話型の利用枠とは別の枠（月額相当のクレジット）を消費する構造に変わっています。本書でメインに扱う対話型の利用は、サブスクリプションの通常枠を使います。詳細は第14章で改めて整理します。

## 「あなたの開発では」—最初に試す1つのこと

ここまで Claude Code の全体像を説明しましたが、一番早い理解は「実際に動かす」です。セットアップが完了したら、最初に試してほしいことが1つあります。

**自分のプロジェクトで「このコードの構成を説明して」と入力してみる**

Claude Code がカレントディレクトリを探索し、「このプロジェクトは〇〇を使っていて、構成は…」という応答を返してきたとき、「あ、ファイルを読んだ上で答えている」という感覚が体に入ります。その感覚を体験してから、第2章（`CLAUDE.md`）へ進んでください。

Cursor や Copilot に慣れている方は「IDE から離れることへの抵抗」を感じるかもしれません。ただ Claude Code は、IDE から完全に切り替えるツールではなく、「大きな塊の作業を任せる」ために添える選択肢です。慣れてきたら IDE と CLI を往復する使い方が自然に生まれます。

## 章末まとめ

- Claude Code は **CLI ツール**。コードベースを探索し、ファイルを読み書きし、コマンドを実行する
- Web の Claude チャット画面との最大の違いは「ファイルシステムと直接やり取りする点」
- Cursor・GitHub Copilot とは競合ではなく補完。「まとまった変更・複数ファイル連携・サブエージェントとの協調」は Claude Code が得意
- セットアップは `curl -fsSL https://claude.ai/install.sh | bash`（macOS/Linux）→ プロジェクトで `claude` → 初回認証
- Node.js は不要（Native インストール版を使う場合）
- プランは **Pro から試して、毎日当たるようになったら Max 5x を検討**（詳細は第14章）
- 各コマンドやオプションの詳細は更新が速いので、公式ドキュメントを正典とする

---

Claude Code をインストールし、初めて起動したとき、何も設定しない状態ではプロジェクトについての「記憶」がありません。セッションを終了すると、前回話したことは消えます。毎回「このプロジェクトは TypeScript で、テストは Vitest で…」と説明し直す必要があります。

この問題を解決するのが `CLAUDE.md` です。次章では、Claude Code の「プロジェクト記憶」として機能するこのファイルの書き方を扱います。
