# 序章 なんとなく使っている、から卒業する

Claude Code を使って開発してみよう——そう思って Pro プランを契約した。インストールはした。でも、何から始めればいいか分からない。サブエージェントという言葉を見かけたが、自分の開発フローにどう組み込むのか見えない。そういう状態から、本書で何が変わるのか。

本書が目指すのは「チャットボットに指示を出す」から「役割で動くサブエージェントを設計・運用する」への発想の切り替えです。この序章では、その変化の全体像と、本書があなたに提供する具体的なゴールを整理します。

---

## 「なんとなく」の正体

「なんとなく使っている」とはどういう状態でしょうか。

- `CLAUDE.md` の名前は聞いたことがあるが、書いていない
- サブエージェントという言葉を知っているが、1人の個人開発に使えるイメージが湧かない
- 毎回同じことを書いたプロンプトを送っている
- 長いセッションが詰まってきたとき、どうリセットするか手探りでやっている
- 商業書を1冊買ったが、「組織導入」「チーム開発」の話ばかりで自分の使い方に当てはまらなかった

この状態を1文で言い換えると、「Claude Code を1体のチャットボットとして使っている」です。

Claude Code はチャットボットとして使えますが、それだけではありません。プロジェクトのコードベースを読み込み、役割を持った複数のサブエージェントを並列で動かし、繰り返す作業をコマンドとして再利用できる仕組みを持っています。「なんとなく」の正体は、この仕組みに手をつけていないことです。

---

## 本書で何が変わるか

以下の表は、本書を読み終えたときの「発想の変化」を並べたものです。

| Before | After |
|--------|-------|
| Claude Code とチャットで質問・回答を繰り返す | サブエージェントに役割を持たせて並列で働かせる |
| `CLAUDE.md` を書いていない（または空） | `CLAUDE.md` と2〜3体のエージェント定義を設計できる |
| 「Cursor と何が違うの？」が言語化できない | Claude Code 固有の強み（コードベース理解・Hooks・Plan mode）を自分の作業に組み込める |
| 商業書を読んでも「自分の規模には大きすぎる」と感じる | 2体構成から始めて、詰まりを感じたら役割を1つ足す進め方が体に入っている |
| 月額の費用が投資として正当化できない感覚がある | 自分の開発フローに対するコストと効果を言葉で説明できる |

具体的には、本書を読み終えたとき、あなたは次のことができる状態になっています。

- `CLAUDE.md` を書ける（最小テンプレートから始めて、育てる方法がわかる）
- `.claude/agents/writer.md` と `.claude/agents/reviewer.md` を自分のリポジトリに置き、コミット前に reviewer を回せる
- よく使う作業をスラッシュコマンドとして再利用できる
- Hooks・Agent Skills のうち、自分の作業フローで使うものを1〜2個セットアップできる

## 本書の立ち位置

2026年6月時点、Claude Code を扱う書籍は商業出版・個人出版ともに増えています。本書がそれらと何が違うのかを正直に書いておきます。

**商業出版の入門書**は、開発チームへの導入・組織での活用が主眼です。1人で副業プロダクトを開発しているエンジニアが「自分の開発フローのどこに、どの役割を何体入れるか」という具体的な判断基準は、あまり扱われていません。

**「一人でAIチームを持つ」系の個人出版**は、経営者・クリエイター・個人事業主が対象です。TypeScript や Python を書くエンジニアが、実装フローの中にサブエージェントをどう組み込むかは、そこでも扱っていません。

本書が補おうとしているのは、その空白です。

具体的には、3つの軸に絞っています。

**1. エンジニアの個人開発フロー × サブエージェント体系**

「副業で個人プロダクトを作っている」「会社では Copilot を使い、個人開発で Claude Code を使っている」——そういう1人のエンジニアの作業フローの中に、どの役割を何体・どこに置くかを体系化します。まず2体（writer + reviewer）から始め、詰まりを感じたら3体目を足す、という積み上げ方を主軸にします。

**2. 失敗の一次情報**

本書の著者は、自身のエージェントチームの運用で複数の事故を起こしています。「AI が存在しないライブラリの API を書いた」「レビュアーに書き換え権限を渡したら勝手に実装を修正した」「コンテキストを圧縮しすぎて前の指示が消えた」——これらは商業書には載りません。失敗から導いた設計上の判断基準（どの役割に何の権限を渡すか、いつコンテキストをリセットするか）を、実用形で提示します。

**3. 「最新機能の網羅」は本書の軸ではない**

Hooks・Agent Skills・Plan mode は本書でも扱いますが、「機能を網羅している」こと自体は差別化にしません。扱うのは「1人の開発フローのどこに、どう仕込むか」という文脈限定の話です。機能の詳細は公式ドキュメントが最も正確で最新ですので、本書では「なぜ使うか」「どこに置くか」に絞ります。

## 本書の構成

本書は5部構成です。

**第1部（第1〜3章）: Claude Code の基礎を1人で固める**

CLI セットアップ・`CLAUDE.md`・スラッシュコマンドを扱います。「基礎は知っている」なら読み飛ばして第2部へ進んでも構いませんが、第2章（`CLAUDE.md`）は後の章の前提になるので確認することを勧めます。

**第2部（第4〜6章）: サブエージェントという発想**

なぜ1体だけで使うと限界が来るか、サブエージェントの定義ファイル構造、役割を増やすときの判断軸、を扱います。

**第3部（第7〜9章）: 動かしてみる—最小2体構成**

writer + reviewer の動かし方（第7章）・3体目の判断（第8章）・委任指示書の5要素（第9章）を扱います。コピペ可能なサンプルを含みます。

**第4部（第10〜12章）: 最新機能を1人で使い倒す**

Hooks・Agent Skills・Plan mode を1人開発の文脈で解説します。

**第5部（第13〜15章）: 1人運用のリアル**

失敗パターン・コストとROI・業務別の構成例を扱います。

## この本を読む前に確認すること

本書は以下を前提にしています。

- Claude の Pro プランまたは Max プランを契約しているか、契約を検討している
- コマンドラインの基本操作ができる（`cd` でディレクトリを移動し、コマンドを実行できる）
- TypeScript / JavaScript・Python・その他の言語を日常的に書いている

「Node.js を入れたことがない」という場合は、第1章の CLI セットアップのところで手を動かすことになります。それ以外の前提知識は特に必要ありません。

**詰まったら Claude Code 自身に聞く**

本書を読み進める中で「この機能の詳細を知りたい」「自分のプロジェクトではどう設定すればいい？」という疑問が出てきたとき、Claude Code 自身に聞くのが最速です。「CLAUDE.md に何を書けばいい？」「このコマンドはどんな場面で使う？」——こうした問いをそのまま投げてみてください。本書では「なぜ使うか」「どこに置くか」を扱いますが、機能の詳細や最新情報は Claude Code が持っています。

---

では、始めましょう。第1章では、Claude Code とはそもそも何か——Web のチャット画面・Cursor・GitHub Copilot とどう違うのかを、1人開発者の視点で整理します。「基礎は知っている」なら第2章から入ってください。
