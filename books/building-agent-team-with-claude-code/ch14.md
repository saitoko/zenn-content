# 第14章 コストとROI—月額$20/$100/$200の境界

この章の結論を先に言います。副業や個人開発で Claude Code を使う多くのエンジニアにとって、プランを上げる損益分岐点は、最初に想定するより低いところにあります。「高い」という印象は計算してみると変わる——これを確認することが、この章の目的です。

Claude Code を使い続けるなら、いずれ「Pro のままでいいのか、Max に上げるべきか」という判断に直面します。Pro は $20、Max 5x は $100、Max 20x は $200。月額 $100、円にして約15,000円。「開発ツール1本に毎月この出費は、さすがに高い」。多くの人が、まずここで身構えます。私もそうでした。月額が5倍・10倍と跳ね上がる中で、自分はどこに立つべきなのか。

ところが、この「高い」という先入観を一度だけ計算にかけてみると、印象は大きくひっくり返ります。結論を先に言えば、損益分岐点は思っているよりずっと手前にあります。この判断を「なんとなく高そう」「とりあえず一番安いプランで」で済ませると、本来得られたはずの時間を取り逃します。逆に、使っていないのに高いプランを契約し続けるのも無駄です。この章では、3つのプランの境界線を「週あたりの利用時間」と「節約できた時間の金額換算」という2つの軸で引きます。読み終えたとき、あなたは自分の使い方に対するプラン選択を、感覚ではなく計算で説明できる状態になっています。

---

## 3つのプランと境界線

Claude Code の利用は、Anthropic の Claude サブスクリプション（Pro または Max）と連携します。2026年4月時点のプランと月額は以下の通りです（価格は変動するため、契約前に必ず公式サイトで確認してください）。

| プラン | 月額（概算） | 向いている使い方 |
|--------|------------|--------------|
| Pro | $20/月 | Claude Code を試し始める段階。週に数回の利用 |
| Max 5x | $100/月 | 毎日1〜2時間以上 Claude Code を使う。Pro の制限に当たる場合 |
| Max 20x | $200/月 | Claude Code をメインの開発ツールとしてほぼ常時使う |

なお、テーブルの「毎日1〜2時間以上」などの利用目安は、Anthropic 公式が定める厳密な閾値ではなく、著者が使ってきた体感にもとづく目安です。正確な利用枠は後述の通り公式ヘルプセンターで確認してください。

境界線を分けるのは「利用枠（使用量の上限）にどれだけ当たるか」です。各プランには一定時間ごとにリセットされる利用枠があり、それを使い切ると次のリセットまで待つことになります。上位プランほど枠が大きく、プラン名の「5x」「20x」はその枠の大きさ（基準に対する倍率）の目安を表しています。プラン名の数値だけで単純計算すれば、Max 20x は Max 5x のおよそ4倍（20x ÷ 5x）の枠を持つことになります。ただしこれはあくまでプラン名からの推測であり、実際の枠倍率や上限はプラン改定で変わります。正確な枠の大きさは Anthropic 公式ヘルプセンターの最新情報で確認してください。

判断の出発点はシンプルです。

- **試し始める段階なら Pro から**。週に数回、まとまった作業で使う程度なら $20 で足ります
- **Pro の枠に毎日のように当たるようになったら Max 5x へ**。「もう少し続けたいのに枠で止まる」が頻発したら、それが移行のシグナルです
- **Max 5x でも枠に当たり、Claude Code が開発の主軸になっているなら Max 20x へ**

第1章で「Pro から始めて、当たったら上げる」という方針を示しました。この章はその「当たったら」の中身を具体化します。

## ROI の考え方—「節約できた時間」を金額に換算する

**30秒で読める結論:**

計算の手順は3ステップです。(1) 自分の時間単価を1つ決める (2) Claude Code が月に何時間を節約しているか見積もる (3) 節約時間 × 時間単価 が月額を上回ればOK。以下で順に説明します。

プランの月額が高いか安いかは、単体では決まりません。「その金額で何時間取り戻せるか」、そして「取り戻した時間に価値があるか」と並べて初めて判断できます。後者は当たり前に思えるかもしれませんが、ROI が成立する地味な前提なので、頭の片隅に置いておいてください（章末で改めて触れます）。

副業や個人開発でコードを書くあなたにとって、最も分かりやすい換算軸は **「1時間を節約できたら、その1時間はいくらの価値か」** です。

ここで「自分の時間の金額換算」を厳密に出す必要はありません。置き方はシンプルに2択で考えてください。**副業単価があるならそれをそのまま使う。なければ「この1時間を取り戻せるなら払ってもいい額」を直感で置く**——これで十分です。どちらもピンとこなければ、次のような手がかりで置いても構いません。

- 本業の月給 ÷ 月160時間（月給30万円なら時給約1,900円）
- 残業したときの割増時給

重要なのは、月額という固定費を「時間」という自分の資源と同じ単位に並べることです。

> **著者の換算の置き方**
>
> 私は自分の作業時間を「取り戻せるなら払ってもいい額」で置いています。厳密な時給ではなく、「この退屈な30分が消えるなら、いくらまでなら出すか」という基準です。この置き方だと、ROI が「黒字か赤字か」の冷たい計算ではなく、「払った分、自分の時間が返ってきているか」という体感に近づきます。

ここまでの考え方を、実際の数字で損益分岐点に落とし込んでみます。以下はすべて、私の試算による概算であり、実測値ではありません。為替は2026年6月時点の概算で1ドル≒150円として計算しています。

**例: Max 5x（$100/月）を契約する場合**

- 月額 $100 ≒ 15,000円
- 自分の時間を仮に時間あたり3,000円と置く
- 損益分岐点 = 15,000円 ÷ 3,000円 = **月5時間**

つまり、Max 5x が月に5時間以上を取り戻してくれるなら、$100 は元が取れている計算になります。

これを副業の作業時間と並べてみます。週10時間で副業開発をしているなら、月の作業時間はおよそ40時間です。そのうち5時間——全体の約12%——を Claude Code が節約すれば、Max 5x の月額は回収できます。

たとえばフロントエンド開発なら、「既存の React コンポーネントの構成や props を読み解く」「TypeScript の型定義を生成する」「コンポーネントのテスト雛形や Storybook のひな型を書く」「レビュー観点を一通り当てる」といった作業がこれにあたります。こうした地味だが手間のかかる作業を Claude Code に任せることを考えると、この12%という水準は、私の体感ではそれほど高いハードルには感じませんでした。writer + reviewer の2体構成（第7章）が機能し始めると、型定義の生成やレビュー観点の洗い出しだけでこの水準に届くと感じる場面が少なくありませんでした（あくまで私自身の体感であり、節約幅は使い方によって大きく変わります）。

月単位では小さく見えるコストも、年単位で節約時間と並べると印象が変わります。先ほどの損益分岐点の計算（月額 ÷ 時間単価 = 月あたり何時間）に、あなた自身の時間単価と週あたりの節約時間を入れて計算してみてください。月額 $100 という数字だけ見ると身構えますが、年単位で「節約時間 × 時間単価」と並べると、回収ラインは思っているより手前にあることが分かります。

同じ計算を Pro と Max 20x にも当てはめると、損益分岐点は次のようになります（時間単価3,000円・1ドル150円の場合の試算）。

| プラン | 月額（概算） | 月あたり損益分岐点 |
|--------|------------|-----------------|
| Pro $20 | 約3,000円 | 月1時間 |
| Max 5x $100 | 約15,000円 | 月5時間 |
| Max 20x $200 | 約30,000円 | 月10時間 |

Max 20x ですら、月10時間——週あたり2〜3時間の節約で損益分岐に達します。プランが高く見えても、節約時間に換算すると「思ったより低い水準で元が取れる」ことが分かります。

## 「コストが不安なら先に計算する」という習慣

プランをまたぐ判断や、自動化を始める前の不安は、たいてい「いくらかかるか分からない」ことから来ます。これは、先に計算する習慣で解消できます。

Claude Code には、コストを把握するための手段が用意されています。

- **`/cost`**: 現在のセッションで消費した概算コストを表示します。「この作業でどのくらい使ったか」をその場で確認できます
- **公式サイトの利用状況画面**: 月単位の消費を確認できます

不安を感じたときの動き方は、シンプルです。

1. **新しい使い方を始める前に、小さく試して `/cost` を見る**。「この種の作業1回で、だいたいこのくらい」という感覚を先に掴む
2. **その単価を月の頻度で掛ける**。「1回あたり◯◯、これを週5回なら月20回、つまり月◯◯」と概算する
3. **概算が月額に対して見合うかを、先の損益分岐点と並べて判断する**

この「先に小さく試して単価を掴み、頻度で掛ける」という手順を習慣にすると、コストは「使ってみたら高かった」という事後の驚きではなく、「始める前に見積もれるもの」に変わります。とくに非対話型の自動化を組む前は、必ず1回分の消費を実測してから本格運用に移すことを勧めます。自動化は人手を介さずに枠を消費するため、見積もりなしで回すと消費が読めなくなります。

## 「あなたの開発では」—自分のプランを計算で決める

ここまでの内容を、あなた自身のプラン選択に当てはめてみます。手順は3ステップです。

### ステップ1: いま枠に当たっているかを実測で確認する

最初の判断材料は記憶ではなく実測です。公式サイトにログインし、アカウント設定の「Usage（利用状況）」画面を開いてください。ここでは直近の枠の消費が日単位・期間単位で確認でき、上限に対してどれだけ使ったか（残りがどれくらいか）が一目で分かります。過去1週間ほどを見て、Pro で「枠の上限に張り付いている日」が続いていたり、「もっと続けたいのに枠で止まる」が週に何度も起きているなら、それが Max 5x への移行シグナルです。逆に、画面を見ても枠に当たった記録がほとんどないなら、まだ Pro で十分。プランは「当たってから上げる」で間に合います。

### ステップ2: 自分の時間単価を1つ決める

時間単価の置き方は先述の通り、「副業単価があればそれ、なければ払ってもいい額」の2択で十分です。3,000円でも5,000円でも、自分が納得できる額を1つ決めてください。

### ステップ3: 損益分岐点と節約実感を並べる

計算式も先述の通りです。検討中のプランの損益分岐点（月額 ÷ 時間単価 = 月あたり何時間）に、ステップ2で決めた自分の数字を当てはめてみてください。出てきた時間数を、Claude Code が実際に節約していそうな時間と比べる——節約時間が損益分岐点を上回っていれば、そのプランは計算上成立しています。

週10時間の副業開発でも、この計算をすると Max 5x の損益分岐点（月5時間）は意外と低いことが見えてきます。「高いから Pro のまま」と感覚で止めず、一度この計算をしてみてください。私の体感では、感覚で迷うより計算で線を引いたほうが判断しやすい場面が多いはずです。

今すぐ試してみてください。検討中のプランの月額を、自分の時間単価（本業の月給÷160時間でも、払ってもいい額でも何でも）で割る。出た数字が「月何時間節約すればOKか」の答えです。その時間を Claude Code が節約しているかどうか——それだけで決断できます。

**5分でできる確認**: (1) 先週 Claude Code を使って何時間作業しましたか？ (2) そのうち、Claude Code なしでは1.5倍以上かかった作業は何件ありましたか？ (3) その件数 × 節約時間が月間の損益分岐点を超えていれば、今のプランは回収できています。この3問、今すぐ頭の中で試してみてください。

## 章末まとめ

- 3つのプランの境界は「利用枠にどれだけ当たるか」で分かれる。Pro（試す）→ Max 5x（毎日1〜2時間以上）→ Max 20x（ほぼ常時）。試し始めは Pro、枠に毎日当たるようになったら上げる（2026年6月時点）
- ROI は「節約できた時間 × 自分の時間単価」が月額を上回るかで判断する。時間単価は厳密でなくてよい（本業の月給 ÷ 160時間、残業代の時給、払ってもいい額など、納得できる基準を1つ置く）
- 計算上の黒字が「実感」に変わるかは、浮いた時間の使い道で決まる。そして「どう使えば浮いた時間が増えるか」こそが次章のテーマ——フロントエンド・副業プロダクト・データ分析の3パターンで、最小チーム構成を具体的に示す
- 損益分岐点は思ったより低い。時間単価3,000円・1ドル150円の試算で、Max 5x は月5時間、Max 20x でも月10時間の節約で元が取れる（いずれも著者の試算による概算。料金は変動するため契約前に公式サイトで最新価格を確認する）
- コストが不安なら先に計算する。`/cost` で1回分の単価を実測し、頻度で掛けて月額と並べる習慣を持つ

---

プランとコストの判断軸が手に入ると、Claude Code を「いくらの投資か」だけでなく「どう使えば投資が回収できるか」で考えられるようになります。次章では、フロントエンド開発・副業プロダクト開発・データ分析の3パターンで、それぞれに合った最小チーム構成を具体的に示します。
